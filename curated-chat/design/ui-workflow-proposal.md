## 1. 현재 구현과 제안의 경계

검토한 저장소 기준 커밋은 `b1d3e94bcd7f50d5e2de3ade4d1de7ea58bcafdf`이다. 현재 README와 `supabase/functions/query-agent/index.ts`를 읽었으며 후보 검색에 `match_chunks_keyword` RPC를 호출하는 것을 확인했다. 따라서 이 문서를 벡터 검색·임베딩 시스템 구현 증거로 사용하지 않는다.

현재 트리의 라우트는 `__root.tsx`, `auth.tsx`, `documents.tsx`, `index.tsx`다. 아래의 최적화 라우트 세 개는 이 트리에 없으며 **설계 후보**로만 보존한다. 서버 실행, DB 상태, 배포 화면은 이번 정리에서 검증하지 않았다.

## 2. 목적과 사용자 흐름

기존 기능을 다시 만드는 대신, 사용자가 다음 행동과 답변의 근거를 이해하기 쉽게 정보 구조를 바꾸는 것이 목적이다.

1. **문서 준비:** 업로드, 처리 상태, 검색 가능한 문서 유무를 보여준다.
2. **질문:** 문서가 준비되면 질문 입력을 주 행동으로 강조한다.
3. **근거 검증:** 답변과 근거 파일·원문 조각을 연결한다.

문서가 없을 때는 업로드 안내를, 준비된 문서가 있을 때는 질문 입력을 우선 노출한다. 검색 이력은 보조 패널이나 접을 수 있는 영역으로 옮긴다.

## 3. 화면 구성 제안

- 질문 입력: 자연어 입력을 중심에 두고 고급 필터는 접힌 상태로 시작한다.
- 용어: Top-K는 ‘참고할 근거 수’, chunk는 ‘근거 조각’처럼 풀어 쓴다. 정확한 기술 용어는 상세 설명에서 병기한다.
- 답변: 요약을 먼저 보여주고 근거 카드, 원문 펼침, 파일별 연결을 바로 확인할 수 있게 한다.
- 문서 관리: 대기·처리 중·완료·오류를 구분하고 오류에는 재시도를 제공한다.
- 모바일: 단일 열과 접이식 필터·이력을 사용한다. 큰 표는 카드형 목록으로 바꾼다.
- 접근성: 키보드 초점, 버튼 이름, 비활성 이유, 색 이외의 상태 라벨을 제공한다.

이는 사용성 개선 **가설**이다. 질문 시작 시간 감소나 신뢰 향상은 측정되지 않았으므로 성과 수치로 적지 않는다.

## 4. 실데이터와 데모 분리

역사적 대화에서 제안한 라우트:

| 제안 경로 | 목적 | 경계 |
|---|---|---|
| `/optimized` | 인증된 실제 문서 흐름의 개선 UI | 기존 인증·소유권·API 계약 유지 |
| `/optimized-demo` | 로그인 없는 발표용 화면 | 명시적인 가상 데이터만 사용, 실제 API 호출 없음 |
| `/ui-comparison` | 기존/제안 UI 비교 | ‘제안’임을 표시하고 구현 효과와 혼동하지 않음 |

기존 `/`, `/documents`, `/auth`를 대체하거나 삭제하지 않는 점진적 접근이다. 당시 언급된 `process-document`, `query-agent` 및 문서·청크·이력 데이터 구조의 호환성을 확인한 뒤 구현해야 한다. 이 노트 자체가 현재 API 계약 전체를 보증하지는 않는다.

## 5. 오해를 막는 표시 규칙

원래 제안에는 실제 서버 단계 이벤트가 없어도 단계별 진행 UI를 연출하는 방안이 있었다. 이를 실제 처리 상태처럼 보여 주지 않는다.

- 실제 경로는 서버에서 확인할 수 있는 상태만 확정적으로 표시한다. 세부 진행을 모르면 일반 로딩 상태를 쓴다.
- mock 경로는 화면과 결과에 ‘시뮬레이션 / 가상 데이터’를 표시한다.
- 신뢰도 표시값은 정확도나 보정된 확률로 단정하지 않는다. 산출 근거가 불명확하면 보조 점수로 설명하거나 숨긴다.
- UI에 임베딩·벡터DB라는 문구가 있어도 실제 구현으로 간주하지 않는다.

이 표시 규칙은 역사적 제안을 정리하면서 추가한 정확성 보호 기준이며, 당시 구현 결과가 아니다.

- [ ] 로그아웃이나 인증 만료 후 다른 사용자의 문서/이력이 보이지 않는가?

- [ ] 근거 카드를 눌렀을 때 대응하는 원문이 열리는가?
- [ ] mock 화면이 실제 조회·업로드·삭제 요청을 보내지 않는가?
- [ ] 처리 중 반복 클릭, 취소, 뒤로 가기에도 상태가 일관적인가?
- [ ] 키보드와 좁은 화면에서 모든 동작에 접근할 수 있는가?
